# Enact ambiguity and desktop support audit

Audited on 2026-10-29. Reviewed the skills, all role prompts, helper,
configuration, tests and design notes, plus the desktop tools available in
the auditing chat. The checkout changed during the interview: intake merged
back into `/enact`, worktrees moved inside the project, and local branch
tracking was added. This report accounts for those changes through
`48ae22b`.

The agreed behavior is recorded in [design.md](design.md). This report does
not implement the runtime changes or claim that the desktop flow was tested
end to end.

## Findings that need fixes

### P1: completion can abandon final validation and Steward work

`schedule()` returns `done` as soon as the epic is closed and this vizier has
no open assignments, before considering ready Steward beads. It does not
check CI or whether the run's delivered commits reached `master`. The skill
then removes the Marshal. A final CI failure can arrive after all
orchestration has stopped.

Track final delivery and validation through run completion, including
Steward fixes. Use commit ancestry so unrelated later pushes do not make a
finished run wait forever for staging to become idle.

### P1: same-machine viziers share a reservation identity

`schedule()` claims as `vizier:<hostname>`, while `claim()` checks only that
assignee to decide whether it won. Beads claims are idempotent for the same
actor. Two viziers on one machine, including different providers, can both
accept a reservation and overwrite `enact_vizier` after reading the same
ready work.

Reproduced with real git, Beads and Dolt in a temporary repository: two calls
with distinct vizier metadata and the same machine actor both returned
success; the second replaced the first vizier. Give reservations a unique
vizier identity and verify ownership through handoff and reassignment.

### P1: recovery cannot distinguish providers on the same machine

`cmd_status()` selects workers by `enact_spawn_host` alone. Active worker
records do not capture the spawning provider or app surface;
`enact_provider` is a targeting constraint, not a record of the actual
creator. Marshal recovery then assumes Claude session tools and treats a
failed lookup as proof the chat is gone.

Persist enough routing information to inspect, message and archive the
correct chat through its host tools. A transient lookup failure or an
unsupported tool must not release a live worker's bead. Prevent a previous
worker from continuing to mutate a bead after its ownership changes.

### P1: abandoned worktrees cannot follow the documented recovery path

The Marshal releases abandoned beads for a worker with a fresh worktree.
Release preserves the old worktree and branch, but `create_worktree()`
rejects an existing path. Common instructions also forbid touching another
session's worktree without defining a recovery handoff.

Implement the agreed recovery ownership and preservation rules, including
the case where a replacement is on another machine. Preserve the location
of unfinished work instead of clearing the only useful recovery pointers.

### P1: pause and blocked states do not exist in the runtime contract

The skill interprets "stop" only within the current vizier turn. The helper
does not enforce a shared pause or terminal blocked state. A peer can keep
spawning, and automatic recovery could undo the user's stop. Releasing an
impossible bead can produce endless replacement attempts.

Record these states in the shared graph and check them before claiming or
resuming work. Preserve unmet acceptance criteria when blocked. Do not
silently close an impossible requirement as though it had been delivered.

### P1: the desktop adapter is incomplete

The Codex spawn instruction only says to call `create_thread` with a prompt
and title. The available tool also requires a project selected through
`list_projects` and an execution target. Enact needs the local project
checkout; its own helper creates worker worktrees. The instructions omit
the mapping from role `effort` to the tool's `thinking` field, the handling
of unavailable model settings, and the distinction between a ready
`threadId` and a pending `clientThreadId`.

Document actual tools for listing, reading, waiting, messaging and archiving
chats, plus project selection, model fallback, returned identities and any
required created-chat UI output. Check tool availability and local access
before claiming work. A non-prompting approval policy alone does not prove
the required operations can succeed. Keep top-level role chats; subagents
do not satisfy Enact's session contract.

### P1: Marshal scheduling and recovery lack a desktop implementation

The skill says "automation" without specifying how to discover, reuse,
create and remove the project sweep through the current automation tool.
Its schedule name uses only the project basename, so unrelated projects can
collide. Cleanup checks working beads rather than all active runs, which
can remove a shared sweep while another vizier is between assignments.

Define a standalone project sweep with stable project and host identity,
carry the run's orchestration authorization, and keep it while any relevant
run still needs recovery. Implement bounded automatic vizier resume on
capable hosts while respecting shared paused and blocked states. Store the
state needed for repeated nudges; role text currently refers to previous
sweeps without defining where that history lives. Notifications should
report meaningful changes rather than healthy hourly sweeps.

The Marshal also needs a usable staging tip: its instructions compare that
tip with `ci.last_tested`, but `cmd_status()` does not return the tip.

### P2: later pushes erase the bead's earlier commit record

`cmd_push()` replaces `enact_commits` with the newest push's commits. Warden
and Mason use this metadata to find delivered work, so earlier changes can
be omitted from review. Reproduced with two real pushes for one bead: two
commits were delivered, but only one remained in the metadata.

Preserve the full delivered commit record. Also make bookkeeping recoverable
when git push succeeds but metadata sync fails: a retry currently returns
"nothing to push" before repairing the missing record or starting CI.

### P2: long waits assume a tool call this desktop session cannot make

The skill asks for one foreground call with a 600000 ms timeout and calls
the Codex equivalent a "long-yield exec". The available execution tool yields
a process identity much sooner. Treat the long-running helper as one
process and resume it with supported bounded waits; do not start another
`next` process each time the tool yields. Preserve mid-run user steering.

### P2: installation can omit the documented user skill directory

`skill_dirs()` skips a candidate when its parent is absent. A new machine
with `.codex` but no `.agents` can receive links only in the legacy Codex
location. Ensure the documented `~/.agents/skills` location is created for
supported Codex installations. Verify discovery and avoid duplicate skill
entries when supporting legacy locations.

### P2: process guidance and the implementation have drifted

The design still names an `enact wait` command that is not in the CLI, says
`close` records commits that are actually recorded by `push`, and retains
old pytest and direct-to-master delivery guidance. Follow-up filing lacks
the agreed higher bar. Common worker instructions do not explain how role
restrictions and the Warden policy apply to dynamically filed fixes.

Update runtime prompts together with the helper changes. The dated design
decisions supersede conflicting historical notes until that work lands.

## Validation and remaining limits

- Unit tests passed: five tests on the checkout before the latest branch
  tracking change. The documentation delivery also uses the repository's
  normal fast checks and slow CI.
- Two focused checks used real git, Beads and Dolt in disposable repositories
  and reproduced the reservation and commit-history defects above.
- No role chats or Marshal automations were created during this audit. A
  live desktop smoke test remains necessary after fixes: create a worker in
  the selected project, verify its identity and permissions, deliver work,
  recover an interruption, and verify final CI and cleanup.
- The existing policy permits any machine's passing CI to promote master.
  That is not a guarantee that every supported OS passed. This interview did
  not change that policy or add a cross-platform CI quorum.

## Product references

Official guidance checked on the audit date:

- [Desktop modes and local work](https://learn.chatgpt.com/docs/use-chatgpt)
  describe Work and Codex within the same desktop app. Capability checks
  remain more useful than assuming a separate application for each name.
- [Skill discovery](https://learn.chatgpt.com/docs/build-skills) documents
  `~/.agents/skills`, symlink support, duplicate-name behavior and
  `allow_implicit_invocation: false`. Enact's existing `openai.yaml` policy
  correctly makes Codex invocation explicit.
- [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
  describe a separate delegation mechanism. The current audit compares
  top-level chat management against the tool schemas supplied to this chat.
